# Phase01 QXGA validation

Date: 2026-10-24. DFRobot ESP32-S3 AI Camera v1.1 on COM12, with the user's
replacement 128 GB exFAT card. The firmware was built and flashed successfully;
upload verified the written flash data.

The default changes from VGA to **QXGA, 2048 x 1536**, the OV3660 maximum
supported by [Espressif's camera driver](https://github.com/espressif/esp32-camera/blob/master/driver/sensor.c).
The driver also supports FHD (1920 x 1080). QXGA passed, so FHD was not needed
as a fallback and was not separately flashed in this run.

## Configuration and scope

- Arduino-ESP32 3.3.2; SdFat 2.3.1; OPI PSRAM enabled (8 MB).
- Sensor JPEG quality setting 10, two PSRAM frame buffers, latest-frame capture.
- SD SPI ceiling 10 MHz; exFAT volume capacity 128,144,375,808 bytes.
- Application storage 419,695 bytes; static RAM 33,316 bytes.
- Application binary SHA-256: `b470495e3a683fafc54e9da68ed683d3cf5e099baf8a376cf90dc265312affb7`.

Startup now reports the selected sensor dimensions rather than a hard-coded VGA
label. Firmware checks settling and captured frame dimensions against the selected
mode. The host verifier defaults to QXGA and accepts `--width` / `--height` for
other modes or historical runs. Four USB download protocol tests also pass.

This is a 30-frame QXGA check; the earlier 600-frame VGA run is documented
separately in [the baseline validation](README.md). The root-directory scaling
limit still applies: directory rotation is required for prolonged unattended
recording. File size and latency will also depend on scene detail and lighting.

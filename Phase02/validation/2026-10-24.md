# TMF8829 depth CSV hardware validation — 2026-10-24

Result: **passed** for the depth-only first stage of ADR-0002.

The firmware was compiled and flashed onto the connected DFRobot ESP32-S3 AI
Camera v1.1 on COM12. The MIKROE LightRanger 14 Click was discovered at **I2C
`0x41`, SDA GPIO43, SCL GPIO44**. This is the reverse of the original ADR pin
proposal. Chip identity/revision was `0x9e/0x01`, sensor serial `5064330`, and
application version bytes after RAM patch loading were `[1, 2, 194, 0]`.

The sensor ran at 400 kHz with command `0x41` (8×8 long range), one peak per
zone, dual mode off, histogram dumping off, and a requested 1000 ms period.
The preset's 586 kilo-iterations were retained. Complete configuration readback
matched the programmed bytes. The existing 128 GB card mounted as **exFAT**;
neither formatting nor removal of earlier recordings was performed.

`9c478afcf3a4bc7fdfc4b3e7c0721dac865696db`. See the
[source provenance](../Phase02/src/tmf8829/README.md) for patch bytes/hash and
the MIT licence selection. Build completed without application warnings.

```text
dd5b0911dd961aede2f1c6ba2cacf284d6ec0a1a7e95772d70d72ca06fc9a180
```

Raw serial logs, all downloaded CSVs, per-file SHA-256 hashes and the machine
summary are retained under ignored `Phase02/validation/local/acceptance/`.
The verifier resumed recording after success.

The final bounded USB status check reported `ready=1`, `recording=1`, zero gaps,
zero rejected frames and zero I2C errors, followed by five further frame logs.
At that check the session was `/dtof/s000006`. USB console reconnection can restart
this board, as observed in Phase01; query `STATUS` for the current session rather
than assuming that one software reboot is the only session change. The final
check is retained in `local/final-status.log`.

This verifies desk operation, depth formatting/storage, cadence, rollover and
software restart. **Known-distance 1/5/8/11 m tests have not been performed**;
the long-range preset alone does not establish 11 m performance. Histogram
acquisition, binary storage, power-loss/full-card fault tests and power optimisation
remain later work. The unit tests do not inject malformed native I2C frames into
the running sensor driver.
